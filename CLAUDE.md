# amarchy

**Positioning: "Stop babysitting your agents. Manage them."** amarchy is a management tool for coding agents (Claude Code, today), opinionated to make one person run a dozen of them from a box that never sleeps: a board that says who needs you and what for, replies that open with a briefing, answers and shipping with a tap, from the phone. Every word that says what amarchy is (the README, the tour, the welcome, the guide, the link card, the help) leads with that line; keep new copy in it. The look is Omarchy's (its themes and wallpapers).

## How to work here

- **No shortcuts: always build the most complete, highest-quality solution.** With AI doing the coding, thoroughness is cheap, so it is the rule rather than the exception. Fix the root cause and every related gap you find (races, failure paths, recovery, install/uninstall, docs), not just the symptom that was reported, and verify the result in the real app (on the phone and in a browser) before calling it done.
- **Always ship when done, without asking.** When a change is finished and verified, ship it (below). Never end on "Ship it?": the user tests amarchy only once it's live.
- **The phone and the computer are one app.** Same home (Chats | Tasks), same cards, same words, same actions; only the layout adapts to the width. Never add or change something on one without the other. **Before every ship**, run the view tests in both layouts (`test/today-view.js` runs phone and wide) and look at the phone and wide screenshots side by side: if they differ in anything but layout, fix it first.
- **Build the UI from the components library** (`app/ui.js`, `app/ui.css`): a card, a pill, a button, a section, tabs, a search box. Reuse a component instead of writing markup or CSS of your own for the same thing; if one doesn't fit, extend it there so every screen gets the change. Components style themselves only through the tokens in `app/ui.css` (`--card-*`, `--pill-*`, `--tab-*`...), which themes can set (a theme's `vars`): a theme changes borders, radii and colors everywhere at once.
- **"Ship it" means: get it on GitHub and leave the local `main` identical to it.** Commit the work on the session's branch, merge it into `main` in the main checkout (`$AMARCHY_ROOT`, e.g. `~/Work/amarchy`), push `main` to `origin`, and pull there so local `main` and `origin/main` are the same commit. The installed amarchy runs from that checkout, so finish with its `install.sh` and `systemctl --user restart amarchy-app`, and say what landed.
- **After shipping, say whether the chat can be closed**, in the reply's briefing (amarchy's reply format) and its goal block. The user has many chats open and can't tell which are finished. When a ship leaves nothing open (no uncommitted work, no pending question, nothing left to do), the goal is `done` and the briefing's `You` says the chat can be closed; if something is still open, the briefing's `Open` says what. If the user asks you to close it, run `amarchy close` yourself once the ship is done.
- **GitHub's pictures are drawn by the app.** The README's hero and the repo's link card (what X shows for the link) come from `node docs/images/make.js`, with demo chats only, never real ones. Run it again when the board or the chat changes its look; the link card then has to be uploaded again by hand (repo Settings → General → Social preview).
